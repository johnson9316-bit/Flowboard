## 必修

### 1. 心跳依赖会误杀长时间运行的 run

`lastHeartbeatAt` 只有 `store.heartbeat()` 会刷新（claim 时写入，此后仅此一处更新）；worker 日志、proof、评论都不刷新。而 `flowboardLastActivityAt`（`store-card-helpers.ts:415`）的判定链是 `claim.lastHeartbeatAt ?? execution.updatedAt ?? card.updatedAt` —— 有 claim 时**完全忽略**后两者。

后果：worker 只要没调 `flowboard_heartbeat`（prompt 里有要求，但那是对模型的请求、不是保证），30 分钟后它还在干活，对账就会把 run 关成 failed。同一条 20 分钟规则在旧代码里只用来报 `running_without_heartbeat` 诊断，现在它会动手。

改法：`??` 链换成三者取最大值 —— 任何一次卡片写入都算活动迹象，严格更安全。要更稳可以让 worker 日志和 proof 顺带刷新 claim 心跳。

影响文件：`src/backend/src/store-card-helpers.ts`。

### 2. 清掉 `card-execution.ts` 里残留的死 task 链路

`taskIdFromRuntime`（`card-execution.ts:233`）仍用**卡片自己的 session key** 去 `bindSession` 找任务。这是已修缺陷的同一个根因：任务按 requester session（`agent:main:main`）归属，owner 校验必然失败，所以 `card.taskId` 永远写不进去（实机卡片确认无 taskId）。连带两处死代码：

- `card-execution.ts:455` 的 `bindSession(...).get(card.taskId)` 永不执行；
- `ui/src/pages/projects/project-view.ts:1465` 执行面板的 task 行永远为空。

严重性低（只少一行诊断信息，不影响运行），但它假装自己能用。现实只有一种改法：删掉这条链路。要真做成，得把 requester session key 持久化下来，而派发路径拿不到这个值。

影响文件：`src/backend/src/card-execution.ts`、`ui/src/pages/projects/project-view.ts`。
